Let Claude read your Telegram channels

A small server that collects posts from public Telegram channels and bot chats, stores them in PostgreSQL and exposes them to Claude as a remote MCP connector. Ask Claude for today's job offers, search across channels, filter by hashtags and skip ads, from claude.ai or the Claude mobile app.

What it does

Telegram has no public API for reading channels as a plain user. This connector reads them for you and gives Claude a clean, searchable view.

Public channels

Reads any public channel through its web preview, no account or API key needed. Polled a few times a day and on demand.

Bot chats

Optionally receives messages from groups and channels where your bot is a member, through the Bot API.

Search and hashtags

Case-insensitive search in any language, date filters, and hashtag filters, e.g. skip posts tagged #реклама.

Private by default

OAuth 2.1 with GitHub sign-in: only the GitHub accounts you allow can connect. Old messages are deleted after 90 days.

How it works

The connector sits between Telegram and Claude. Claude never talks to Telegram directly: it calls MCP tools, and the connector answers from its own database.

  1. Public channels (pulled from t.me/s/<channel>) and bot chats (pushed by the Bot API) flow into the connector.
  2. The connector parses posts, extracts hashtags and stores them in PostgreSQL.
  3. Claude calls the connector's MCP tools over HTTPS and gets answers from the database.

Scheduled and on-demand polling

Channels are polled three times a day. When you ask Claude about them and the last poll is over an hour old, the connector fetches fresh posts first, page after page until it has caught up.

Exactly once

Each source keeps a read cursor, so every post is stored once, even across restarts, and deleted posts are never fetched again.

Light responses

Media is summarized as PHOTO or VIDEO ×4, and every message carries a link to the original post, so Claude can cite it.

MCP tools

What Claude can do once the connector is added. Reading tools are annotated as read-only.

ToolWhat it does
list_sourcesChannels and chats the connector reads, with their status.
get_recent_messagesLatest posts of one source, optionally without ads.
search_messagesSearch by text, sources, date, hashtags and exclude_hashtags.
list_hashtagsHashtags channels use as categories, with counts.
add_sourceStart reading a channel (@name or link) or a bot chat (chat id).
pause_source / resume_sourceStop or resume collecting from a source.
refresh_sourcesFetch new posts from all channels right now.

Try asking: "What new warehouse jobs were posted this week? Skip the ads." or "Which categories does this channel use most?"

Security

The connector is its own OAuth 2.1 authorization server, with Claude as its only client. Nothing is reachable without a token it issued.

Connecting Claude

  1. Claude calls /mcp without a token and gets 401 pointing to the protected resource metadata (RFC 9728).
  2. It discovers the authorization and token endpoints (RFC 8414).
  3. You sign in with GitHub; only logins from GITHUB_ALLOWED_LOGINS are let in.
  4. Claude exchanges the code with PKCE S256 for a 1-hour JWT bound to /mcp and a rotating refresh token.

By design

  • Secrets come only from environment variables, never from the repository.
  • Every push is scanned for leaked secrets with gitleaks.
  • Signing keys and authorizations live in PostgreSQL, so deploys do not log Claude out.
  • Unauthenticated requests only reach health checks and OAuth metadata.
  • Messages older than 90 days are deleted every night.

Architecture

Domain-driven design with clean architecture. Dependencies point inwards only, enforced by Maven modules and ArchUnit tests.

connector-bootstrapSpring Boot application, configuration, wiring of use cases, integration tests.
connector-infrastructureAdapters: MCP tools, REST API, scheduler, Telegram web preview parser and Bot API, PostgreSQL with Flyway, OAuth.
connector-applicationUse cases and ports: polling, search, retention. Plain Java, no Spring.
connector-domainAggregates Source and Message, value objects, domain events. No frameworks.

Private channels or full history? Implement one more ChannelFeedPort (for example with TDLib); the domain and use cases stay the same.

Run it yourself

Everything runs in Docker. Any host with HTTPS works; the reference deployment uses Railway.

Locally

git clone https://github.com/Dmytroha/tg_claude_connector
cd tg_claude_connector
cp .env.example .env    # set DB_PASSWORD
docker compose up -d --build

./mvnw verify           # build and tests

Connect to Claude

  1. Create a GitHub OAuth App with the callback https://<your-host>/login/oauth2/code/github.
  2. Set GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET, GITHUB_ALLOWED_LOGINS and MCP_OAUTH_CLIENT_SECRET.
  3. In claude.ai open Settings → Connectors → Add custom connector, enter https://<your-host>/mcp, and under Advanced settings use client id claude and your client secret.

All settings, the REST API and details are in the README.
